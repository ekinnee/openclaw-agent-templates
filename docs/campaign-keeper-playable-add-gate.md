# Campaign Keeper — playable Add gate

This is a release handoff for the existing draft PR. The first target is an **owner-only single-player** Template release that automatically installs its exact engine dependency. Non-owner multiplayer is a later update after the upstream SDK guard. The solo engine's tests and disposable plugin load do not yet establish a playable Agent Template Add or authorize installing an unreviewed plugin on the shared Gateway.

## Critical-path contract on OpenClaw 2026.11.2

1. `templates/campaign-keeper/CLAW.md` currently declares `packages: []`. The local Template schema accepts a plugin dependency only with `kind: plugin`, literal `source: clawhub`, a real package `ref`, and an exact `version` (`/home/openclaw/openclaw/src/templates/manifest-contract.ts`, `schema.ts`). A local `npm-pack:` artifact cannot be named as this portable dependency. The engine is still private `campaign-keeper-engine-spike@0.0.1`, not a reviewed immutable release. Do **not** substitute a made-up ref or republish an incomplete game merely to make the manifest nonempty.
2. The engine registers deterministic `/ck` commands under `operator.write`. For an admitted owner, its command context supplies the host-bound `assertOwnerCurrent` callback, trusted sender/channel/account/thread facts, and `getCurrentConversationBinding()`; the handler checks the exact binding after awaited work and uses the owner assertion for the V2 state effect. This is the *only* currently implemented mutation route. The command path preserves low-cost look/move/item actions without a model turn.
3. A V2 model tool on the installed SDK has `assertInvocationCurrent`, optional `requesterSenderId`, session and delivery facts, but **no exact current plugin-conversation binding effect guard** and no supported way to turn a model tool call into the host's already-authorized `/ck` command dispatch. Fabricating a command context, accepting sender/actor from tool args, or doing a binding snapshot followed by ordinary CAS is not a safe owner-only GM bridge. Therefore an open-ended GM proposal can be *suggested* in prose, but the owner must issue a supported `/ck` command themselves before the GM narrates it as settled. No agent-callable state-changing GM operation exists yet. The optional `/ck scene` reads a bounded projection and continues the model; it does not grant mutation.
4. [OpenClaw PR #196914](https://github.com/openclaw/openclaw/pull/196914) proposes `withCurrentConversationBinding` and a native V2 transaction restriction for command and tool contexts. Until a reviewed contract lands in a **released** host, do not wire an agent tool to this prototype or lift non-owner admission. Even afterward, Campaign Keeper must separately verify real membership/actor ownership, replay, rebind races and two authenticated players; see `campaign-keeper-multiplayer-authority-handoff.md`.

## Smallest honest owner-only demonstration before release

- Use an isolated, token-authenticated Gateway with a separate state root and the exact packed engine. Validate health and host-loaded `/ck`, then admit one real owner through a verified Control UI/channel. Do not treat a synthetic `senderIsOwner` fixture or model-only chat as this proof.
- Run `/ck create`, discover/claim a safety line, let the GM discuss the unscripted lever-tie intent, and have the **owner** execute `/ck brace pump-lever safety-line <id>`. Verify the saved receipt and narration after it. Try an unsupported intent and require a no-effect refusal. Pause, restart only the isolated Gateway, replay the same request ID, and confirm attributes, location, inventory, journal and ending are unchanged. Render and inspect the opt-in stats widget in the actual browser (Gateway UI and separate sandbox origins).
- If the separate Control UI cannot be paired/rendered through a supported route, stop and report that transport/access blocker. Never switch to an exec-origin `openclaw agent` CLI call after its explicit attribution refusal, or install on production merely to manufacture proof.

## Packaging and release sequence

After the single-owner command/GM narration and restart proof pass, review the engine manifest, provenance, save migration policy, package contents and narrow host scopes. Publish one immutable engine version under Erick's verified ClawHub scope *only when the package is genuinely usable*; verify the release and install it by exact version in another disposable state. Then replace `packages: []` with that observed `kind: plugin/source: clawhub/ref/version`, validate/dev/build the Template twice, and run an isolated portable Add from a fresh state. A successful Add must actually install or reuse the declared engine and expose the tested operations; zero package actions from an empty manifest are not success. Keep the PR draft and the Template labeled staging until that proof exists. Published solo support must remain explicitly owner-only while upstream non-owner authority remains unreleased. Two authenticated players, shared obstacle coordination, and non-owner effect authority are *not* gates for the honest solo release; they gate its later multiplayer update.
