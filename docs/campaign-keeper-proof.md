**Blocked; no player tool was registered.** Inspected the public SDK and host wiring in the locally installed-version-matching OpenClaw source `/home/openclaw/openclaw` at `c53c53e749f` (`package.json` version `2026.11.2`). - The v2 `OpenClawPluginToolContext` has a runtime-provided `requesterSenderId`, `agentId`, `sessionKey`, `sessionId`, `nativeChannelId`, `deliveryContext`, and `assertInvocationCurrent` (`src/plugins/tool-types.ts`). The host fills the ordinary tool context from turn options (`src/agents/openclaw-tools.plugin-context.ts`); the v2 factory composes the invocation/source and any separately admitted owner-continuation assertions (`src/plugins/tool-factory-context.ts`). These are useful *individual* facts, but the public tool context has no invocation-scoped `getCurrentConversationBinding` corresponding to the command context, nor a documented effect-time assertion that the exact plugin conversation binding remains assigned to this session. `deliveryContext` is an outbound route, not an attestation that the inbound requester belongs to that plugin binding. A model argument, supplied game UUID, or reconstruction from a channel/session string cannot fill that gap.
- The command SDK does expose `getCurrentConversationBinding()` (`src/plugins/plugin-command.types.ts`), but its non-owner command path has no `assertOwnerCurrent` equivalent. Its authorization recheck for `continueAgent` occurs *after* the command handler returns, not at its state effect (`docs/plugins/sdk-overview/tools-and-commands.md`). Moving the mutation to the ensuing model turn would need the missing bound player tool, not transfer command authority to it.
- The public `inspectConversationBindingAsync` export (`src/plugin-sdk/conversation-binding-inspection-runtime.ts`) is a read-only **session-binding** inspection. It returns a value after awaiting the owner (`src/infra/outbound/session-binding-service.ts`); it supplies no retained predicate or current-binding assertion for the later state commit and is not the command's plugin-binding accessor. Comparing that snapshot before calling CAS leaves a rebind/revocation gap.
- The public V2 `openKeyedStoreV2` action authority and `compareAndApply` do support an invocation-current callback at the state owner (`src/plugin-state/plugin-state-store.types.ts`, `src/plugin-state/plugin-state-store.ts`). That makes atomic receipts/one-row CAS possible, but it cannot prove an unexposed plugin conversation-binding predicate; a pre-CAS inspection followed by `assertInvocationCurrent` is not the same authoritative binding-current guard at final write admission.

The requested conjunction—authenticated non-owner identity, **exact** current plugin conversation/session assignment, and that assignment rechecked inside the same authoritative CAS effect—cannot be established from the inspected 2026.11.2 public SDK. Do not implement a read-only player projection either: a non-owner read without the same exact assignment can disclose another player's saved view. The smallest SDK-side unblock is a public, invocation-bound plugin-conversation identity/binding capability for agent tools with a synchronous `assertCurrent` composable into V2 state action authority (or an equivalent owner-owned conditional CAS predicate). Then add fail-closed two-sender, rebinding-between-read-and-commit, replay and disclosure tests before considering a player adapter. This is a source-contract blocker, not a live-channel experiment or a claim that a future host could not supply the capability.
