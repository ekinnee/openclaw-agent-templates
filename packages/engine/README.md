# Campaign Keeper engine capability spike

Unpublished OpenClaw 2026.11.2 public-SDK prototype; **not safe for live players, multiplayer, or a playable installation**. It implements a bounded six-room authored map slice, but not a complete adventure or combat engine. Do not install, enable, or advertise this package as a game engine.

The `/ck` command requires host authorization and an owner-capable `operator.write` command scope, `senderIsOwner`, and the host's `assertOwnerCurrent` callback. Ordinary non-owner senders fail closed even if the owner approved their sender ID: the public command SDK only provides an after-await current-authority callback for an admitted owner, not for an ordinary authorized sender. A prior `isAuthorizedSender` boolean and UUID possession are not sufficient to revalidate a non-owner before a state mutation. The SDK's later check for model continuation does not guard this command's state writes. Until the SDK exposes a suitable non-owner revalidation path (including an effect guard), there is no safe multiplayer claim. Owner approval is recorded atomically with the game, but cannot enable another player with this SDK.

Command shapes: `/ck create <request-id>`, `approve <sender-id> <request-id>`, `join <game-id> <request-id>`, `look`, `move <room-id> <request-id>`, `examine <object-id> <request-id>`, `talk <pell|suri|mara> <request-id>`, `take <item-id> <request-id>`, `inventory`, `recap`, and `brace pump-lever <request-id>`, `open <pump-hatch|tower-stair> <request-id>`, `roll <grit|wits|charm> <request-id>`, `finish <balanced|diverted|shuttered|deferred> <request-id>`. The Pump hatch now requires a committed solo brace before opening from the Pump House; the two-character lever handoff, Suri assist, and risky unbraced route are still absent. A `finish` action commits an explicit ending and updates active/completed stats. Shuttered requires a prior boats warning, deferred requires a committed evacuation, and the dial/beacon plus a bounded consequence summary settle in the same row. Diversion records Market stock loss unless previously warned. It does not yet enforce every stake, a reflector-fitting operation, or player consensus; deferred is a deliberate command, never an idle timeout. The Pump brace records an improvised support without asserting ownership of an untracked crate. The Tower stair remains a simple deterministic opening. Do not present this as the complete cooperative obstacle. `approve` may only be issued by the game's owner and records a host-scoped sender ID, not a display name or self-selected argument on `join`. `join` requires both matching game UUID and prior owner approval. Request IDs scope persistent replay receipts to an actor; they are not credentials. The owner identity and approval decision are stored in a CAS-protected game row. In this fail-closed prototype only owner actions are executable.

Before reading or writing, the command requires an existing host-resolved plugin conversation binding for this invocation, with binding ID, channel, account, conversation ID and matching thread/parent; it refuses absent/mismatched/changed bindings. Agent/session ID and the exact binding tuple key the game; the retained row also verifies the session key. Nonempty `from` and `to` are required, but the public command context does not itself certify that the raw transport `to` equals the resolved binding destination. Do not claim real-channel destination proof without adapter-level verification. The owner callback is checked after awaited reads, immediately before mutation and after CAS returns; the store's action authority also uses that callback. A binding read is not a transactional guard on the later CAS: revocation/rebinding races between the final lookup and commit still need an SDK-supported binding-current guard or a real adapter-level proof. Thus this remains a capability spike, not an approved channel security boundary.

The new `campaign-keeper-spike-v2` namespace uses a **bounded** 64-row keyed store with `reject-new`, never evict-oldest. Each row allows at most four approvals/players, 64 receipts and 64 KiB of serialized JSON. A full namespace or oversized game refuses new writes; no automatic receipt eviction silently breaks idempotency. The former v1 retained namespace is not opened or migrated by this code; if that code was ever installed, its old rows require separate authorized inventory/retirement. This is not a plugin-wide byte quota across unrelated namespaces, and the storage layer still permits each individual row up to its own cap. No restart/durability test was run.

The trusted host `sessionId` now anchors a distinct incarnation in the same `sessionKey`; `/new` or `/reset` does not inherit the previous game. A missing session ID fails closed. Only accepted `/ck create` commits a row, so opening an empty chat never counts as a game. No migration of older spike rows is attempted. Rows keyed solely by session key, or rows created before `pumpBraced`, `ending`, `dial`, and warning fields existed, fail closed rather than silently reset or become false dashboard zeros. This package has never been installed by this task, but an operator who installed an earlier prototype must inventory its rows and review a versioned migration before use; do not erase them. A release needs an explicit save schema version and migration/recovery tests.

An **opt-in, read-only dashboard widget** and `gameStats` plugin session action are registered only when plugin config explicitly supplies `dashboardEnabled: true` and the Campaign Keeper `agentId`. It requires host `operator.read`, the host-resolved session agent matching the configured agent, a live `allowsAgent` check, and `operator.admin` on shared Gateways. It scans at most 64 authoritative retained rows; malformed, incompatible, mixed-agent, or excess rows return unavailable, not misleading zeros. Every result contains only an opaque game ID, ordinal non-sensitive label, player count, accepted action count, totals and an as-of aggregate version; current spike games are all active and have no end/discovery transition. The query does not expose binding, channel, identities, positions or receipts. The native widget presents aggregate counts only, querying the host-selected session through the read-only action. There is no installed or rendered host proof, text stats fallback, or live multiplayer; installation and UI reload are separate operator steps. The read scan is not a cross-row snapshot and can race with concurrent commits; the version is an aggregate of observed row versions, not a transactionally consistent checkpoint. No restart/durability proof exists.

The local six-room slice has legal movement, two explicit Archive route openings, room-scoped examination with saved public observations, a limited player-facing text projection, inventory, a public journal, unique item claims and CAS receipts. The prototype also records default archetype attributes and Resolve plus an isolated `roll <attribute> <request-id>` result with engine-generated 2d6 in the receipt; this **does not** apply encounter consequences, Resolve loss, or determine a hit/damage outcome. The hidden safety line requires examining the cleat before it can be taken. The fake-CAS item race uses two concurrent requests from **one owner**, not two authenticated players. Three room-checked NPC conversation adapters and Tavern/Market/Archive clue facts are persisted with receipts. This is deterministic content, not open-ended GM dialogue; it does not yet enforce every route through the full cooperative obstacle, character selection, dice-driven NPC/encounter consequences, all clue discovery semantics, complete ending consequences, scene board, or GM tools. `open` is a deterministic test mechanism, not the finished puzzle. A unique-item race test uses a fake CAS store, not a live two-player adapter. Missing: real channel identity and destination proof, safe non-owner authorization after awaits, binding-current effect guard, restart replay, real V2 worker test, full game mechanics, migration, enrollment UX and immutable released plugin dependency. The template is separate and was not changed in this repair.
