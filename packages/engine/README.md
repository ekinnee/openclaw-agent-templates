# Campaign Keeper engine capability spike

This is a local, unpublished OpenClaw 2026.11.2 public-SDK **capability spike, not safe for live players or a playable installation**. It registers `/ck` with `requireAuth: true`, checks an allowed sender and host agent/session identity, and stores a single game per agent/session in a retained `openKeyedStoreV2` namespace. The row also compares channel, account and thread/parent fields, but it does **not** prove an approved physical channel binding. `create`, `join`, and `move` require caller-provided request IDs; CAS protects updates, and stored per-actor receipts are designed to replay responses after conflicts or restarts. Restart replay has not been tested. A game caps at four sender identities and 256 receipts, refusing additional writes for that game, but the namespace has no aggregate cap. `look` is read-only. Failed authorization/storage returns a generic refusal.

Usage: `/ck create <request-id>`, `/ck join <game-id> <request-id>`, `/ck look`, `/ck move <quay|market> <request-id>`. The game ID is displayed on create. **The current `join` implementation accepts any host-allowed sender who knows that ID; it does not implement owner-controlled membership or invitations. Do not use this prototype in an untrusted or shared channel.** The request ID is an idempotency token, not an authentication credential. Native channel sender IDs and agent/session identity are supplied by the host, not parsed from user text. Revalidation of ordinary non-owner player authority after awaited state work is not established by this spike. Exact destination binding must include the host's conversation resolution, not merely session key and nullable channel/account/thread fields. The retained namespace needs a global capacity and byte budget before a release.

Run focused tests from the repository root using an installed 2026.11.2 source tree with `tsx`:
`node --import /home/openclaw/openclaw/node_modules/tsx/dist/loader.mjs --test packages/engine/engine.test.ts`.

This is **not** a released or installed dependency, a complete adventure, a proof of two live authenticated players, or a restart/durability test. There are no dice, clues, GM state, secret player projections, board, migration, enrollment/invite approval, or receipt pruning. The fake-store tests prove command logic and CAS handling only; they do not prove the host's state-worker runtime or plugin load. Do not advertise the template as playable based on this spike.
