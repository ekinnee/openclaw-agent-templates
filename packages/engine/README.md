# Campaign Keeper engine capability spike

Unpublished OpenClaw 2026.11.2 public-SDK prototype; **not safe for live players, multiplayer, or a playable installation**. It implements a bounded six-room authored map slice, but not a complete adventure or combat engine. Do not install, enable, or advertise this package as a game engine.

The `/ck` command requires host authorization and an owner-capable `operator.write` command scope, `senderIsOwner`, and the host's `assertOwnerCurrent` callback. Ordinary non-owner senders fail closed even if the owner approved their sender ID: the public command SDK only provides an after-await current-authority callback for an admitted owner, not for an ordinary authorized sender. A prior `isAuthorizedSender` boolean and UUID possession are not sufficient to revalidate a non-owner before a state mutation. The SDK's later check for model continuation does not guard this command's state writes. Until the SDK exposes a suitable non-owner revalidation path (including an effect guard), there is no safe multiplayer claim. Owner approval is recorded atomically with the game, but cannot enable another player with this SDK.

### Commands

- Start or inspect a campaign with `/ck create [quay-runner|tidehand|lantern-singer] <request-id>`, `approve <sender-id> <request-id>`, `join <game-id> <request-id>`, `look`, `inventory`, `recap`, `scene` (owner-only projection and model continuation).
- Explore with `move <room-id> <request-id>`, `examine <object-id> <request-id>`, `talk <pell|suri|mara> <request-id>`, `take <item-id> <request-id>`, `open tower-stair <request-id>`.
- At the Pump hatch, use `brace pump-lever <request-id>`, `open pump-hatch <request-id>`, `open pump-hatch suri <request-id>`, `risk <pump-hatch|tower-stair> <resolve|surge> <quay|tavern> <request-id>`.
- For checks and recovery, use `roll <grit|wits|charm> <request-id>`, `risk archive-shelf <grit|wits> [nonessential-carried-item] <quay|tavern> <request-id>`, `rest <request-id>`.
- For the finale, use `fit <glass-prism|hand-mirror|improvised> <request-id>`, `warn <boats|market|evacuate> <request-id>`, `finish <balanced|diverted|shuttered|deferred> <request-id>`.

At the Pump House, brace the lever with the weather crate carried from Tide Market, then use `open pump-hatch`. For Suri's help, first commit `talk suri` at Tide Market, then use `open pump-hatch suri` at the Pump House. Both routes open without dice. In an earlier save, use a fresh `talk suri` request in the Market to record her offer. From the Archive, the hatch can be opened directly. An open hatch stays traversable from both sides.

To rush an unbraced hatch at the Pump House, state the stakes and have the player choose the mixed-band cost and retreat room before submitting `risk pump-hatch`. The engine rolls 2d6 + Grit.

| Total | Committed Pump result |
| --- | --- |
| 10+ | Opens cleanly. |
| 7–9 | Opens and costs the selected 1 Resolve or +1 surge. |
| 6 or less | Opens noisily and the wheel jams open. Surge rises by 1. |

At surge 2, a surge cost becomes 1 Resolve. At zero Resolve, the open hatch and consequence commit with retreat to the selected room. `rest` restores 2 Resolve after retreat. The hatch, consequences, public journal entry, actual dice and request receipt save together. Resubmit the same command and request ID after an uncertain response to recover its receipt. An already-open hatch has no new opening cost. The weather crate is the supported brace; improvised bracing and a two-character lever handoff remain authored scenarios.

For the optional Archive shelf, disclose its fixed stakes before requesting the command. On 7–9, omit the item to spend 1 Resolve, or name a carried nonessential item to leave it on the shelf; it remains recoverable in the Archive. The safety line is excluded from this option. On 6 or less, water takes the satchel, reveals a maintenance route and raises surge; at surge 2 supplies are soaked. The engine commits its roll, effect, journal and receipt together. Tavern rest is tracked once before and once after full stakes discovery. The zero-Resolve breather remains available independently.

A `finish` action requires committed stakes from Mara, the Tavern plate, or the Archive plan. Balanced and diverted require a fitted prism, mirror or informed improvised reflector. Shuttered requires a boats warning and deferred requires an evacuation. Diversion costs Market stock unless the Market was warned first. The chosen ending, dial, beacon and consequence commit together and update the game counts. Deferred is a deliberate command.

Only the owner can `approve` a host-scoped sender ID. `join` requires a matching game UUID and prior approval. The current SDK admission gate limits executable actions to the owner. Request IDs identify replay receipts within an actor's actions.

Before reading or writing, the command requires an existing host-resolved plugin conversation binding for this invocation, with binding ID, channel, account, conversation ID and matching thread/parent; it refuses absent/mismatched/changed bindings. Agent/session ID and the exact binding tuple key the game; the retained row also verifies the session key. Nonempty `from` and `to` are required, but the public command context does not itself certify that the raw transport `to` equals the resolved binding destination. Do not claim real-channel destination proof without adapter-level verification. The owner callback is checked after awaited reads, immediately before mutation and after CAS returns; the store's action authority also uses that callback. A binding read is not a transactional guard on the later CAS: revocation/rebinding races between the final lookup and commit still need an SDK-supported binding-current guard or a real adapter-level proof. Thus this remains a capability spike, not an approved channel security boundary.

The new `campaign-keeper-spike-v2` namespace uses a **bounded** 64-row keyed store with `reject-new`, never evict-oldest. Each row allows at most four approvals/players, 64 receipts and 64 KiB of serialized JSON. A full namespace or oversized game refuses new writes; no automatic receipt eviction silently breaks idempotency. The former v1 retained namespace is not opened or migrated by this code; if that code was ever installed, its old rows require separate authorized inventory/retirement. This is not a plugin-wide byte quota across unrelated namespaces, and the storage layer still permits each individual row up to its own cap. No restart/durability test was run.

The trusted host `sessionId` now anchors a distinct incarnation in the same `sessionKey`; `/new` or `/reset` does not inherit the previous game. A missing session ID fails closed. Only accepted `/ck create` commits a row, so opening an empty chat never counts as a game. No migration of older spike rows is attempted. Rows keyed solely by session key, or rows created before `pumpBraced`, `ending`, `dial`, and warning fields existed, fail closed rather than silently reset or become false dashboard zeros. This package has never been installed by this task, but an operator who installed an earlier prototype must inventory its rows and review a versioned migration before use; do not erase them. A release needs an explicit save schema version and migration/recovery tests.

An **opt-in, read-only dashboard widget** and `gameStats` plugin session action are registered only when plugin config explicitly supplies `dashboardEnabled: true` and the Campaign Keeper `agentId`. It requires host `operator.read`, the host-resolved session agent matching the configured agent, a live `allowsAgent` check, and `operator.admin` on shared Gateways. It scans at most 64 authoritative retained rows; malformed, incompatible, mixed-agent, or excess rows return unavailable, not misleading zeros. Every result contains only an opaque game ID, ordinal non-sensitive label, player count, accepted action count, totals and an as-of aggregate version; current spike games are all active and have no end/discovery transition. The query does not expose binding, channel, identities, positions or receipts. The native widget presents aggregate counts only, querying the host-selected session through the read-only action. There is no installed or rendered host proof, text stats fallback, or live multiplayer; installation and UI reload are separate operator steps. The read scan is not a cross-row snapshot and can race with concurrent commits; the version is an aggregate of observed row versions, not a transactionally consistent checkpoint. No restart/durability proof exists.

The local six-room slice has legal movement, two explicit Archive route openings, room-scoped examination with saved public observations, a limited player-facing text projection, inventory, a public journal, unique item claims and CAS receipts. The prototype also records default archetype attributes and Resolve plus an isolated `roll <attribute> <request-id>` result with engine-generated 2d6 in the receipt; this raw roll **does not** apply encounter consequences or determine a hit/damage outcome. The hidden safety line requires examining the cleat before it can be taken. The fake-CAS item race uses two concurrent requests from **one owner**, not two authenticated players. Three room-checked NPC conversation adapters and Tavern/Market/Archive clue facts are persisted with receipts. The game-creator-only `/ck scene` command reads a bounded committed player projection and hands it to the GM agent through `continueAgent`; it is not an independently observed model turn and does not grant the GM state mutation. Its prompt cannot erase prior chat context or privately held GM source; spoiler-safe **model narration** needs a real agent-level adversarial test, not just this projection assertion. Deterministic look/move/item commands still bypass the model. NPC command text remains deterministic, not open-ended GM dialogue; it does not yet enforce every route through the full cooperative obstacle, free-form character creation, dice-driven NPC/encounter consequences, all clue discovery semantics, complete ending consequences, scene board, or GM tools. The Tower stair opens deterministically, and an optional solo Grit risk opens it on every roll band with the selected 7–9 cost and capped-surge fallback. Two-character leverage coordination is still absent. A unique-item race test uses a fake CAS store, not a live two-player adapter. Missing: real channel identity and destination proof, safe non-owner authorization after awaits, binding-current effect guard, restart replay, real V2 worker test, full game mechanics, migration, enrollment UX and immutable released plugin dependency.
